        Submitting
        
        
        
        A settlement is only sent for approval when “Submit for approval” is ticked on the run, and only if every document made it into the draft — anything left over stays a draft. This confirmation is the last stop before it leaves for your approver.
        
      
        

      
        
        
        When something goes wrong
        
        
        
        The run pauses with Chromium still open on the problem, so you can put the page right by hand and have it try again — or leave that document out, or stop the run. Unticked, it never stops to ask: a document that will not file is noted and skipped, and a failure that ends the run is reported, exactly as before.
        
        
        
          
          
          seconds
        
        
        
        A question nobody answers takes the option the run would have taken on its own — so a queue is never held up by a window nobody is looking at. Set 0 to wait for as long as it takes.
        
      
        

      
        
        
        Appearance
        
        
        Auto follows your macOS appearance and turns with it.
        
        
        
          
          
          
        
        
        
        Applies as you pick it — this one is not waiting on “Save settings”.
        
      
        

      
        
        
        Browser
        
        
        
        The Browser pane mirrors the run either way. Left off, Chromium keeps a real window but parks it off your screen, and brings it back if the run stops to ask something that needs the page put right by hand. Turn this on for no window at all — and no stepping in by hand if indfak2 asks something unexpected.

        Getting your TOTP secret
        
      
          
        
        1. Log in to indfak2.dk in your browser and open your account security settings.
          2. 
        
        2. Start re-enrolling two-factor authentication. A QR code appears — and printed
            directly underneath it is a 16-character code, shown so you can type it into an
            authenticator by hand. That code is the secret.
          3. 
        
        3. Copy-paste that 16-character code into the field here. Copy it exactly as shown;
            if indfak2 prints it in spaced groups, delete the spaces first.
          4. 
        
        4. Finish the enrolment as usual — scan the same QR code with your phone’s authenticator app.
            Both it and this app then generate the same codes from that one secret.
          5. 
      
        
      
        
        The code is A–Z and 2–7 only — never a
        0, 1, 8 or
        9. It is not the 6-digit number your authenticator shows: that one
        changes every 30 seconds, while this one is the fixed seed it is generated from, and you copy it once.
      
        
      
        
        The repository also ships setup-totp.js, which drives the same flow in a
        scripted browser and reads the secret out of the QR code for you.
